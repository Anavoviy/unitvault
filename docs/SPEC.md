##  1. Обзор проекта

### 1.1 Описание
UnitVault — локальное desktop-приложение для детального моделирования юнит-экономики. Главный фокус сделан на трёх вещах: **безопасность данных**, **инженерное качество** и **производительность**.

### 1.2 Целевая аудитория
- 🚀 Предприниматели, фаундеры стартапов и продукт-менеджеры.
- 📈 Финансовые аналитики.
- 💼 Все, кто хочет считать юнит-экономику детально, без использования облачных таблиц.

### 1.3 Ключевые принципы
1. **Local-first** — все данные хранятся только локально, без облака.
2. **Security-first** — данные зашифрованы на диске.
3. **Precision** — детальный расчет каждой метрики с учётом edge-cases.
4. **Performance** — мгновенные пересчеты при изменении параметров (благодаря Solid.js сигналам).
5. **Engineer-grade** — покрытие тестами >80%, чистая архитектура, полная документация.

### 1.4 Поддерживаемые бизнес-модели
| Модель | Описание |
|--------|----------|
| **SaaS** | Подписки, recurring revenue. |
| **E-commerce** | Разовые покупки, повторные продажи. |
| **Marketplace** | Двусторонние площадки, комиссии. |
| **Custom** | Пользовательские формулы. |

##  3. Метрики юнит-экономики

### 3.1 Входные параметры

#### Базовые (Обязательные)
| Метрика | Описание | Формат | Валидация |
|---------|----------|--------|-----------|
| **CAC** | Стоимость привлечения клиента | ₽ | > 0 |
| **ARPU** | Средний доход с пользователя за период | ₽ | > 0 |
| **Margin** | Доля прибыли в выручке | 0–100% | 0 < x ≤ 100 |
| **Churn Rate** | Процент ушедших клиентов за период | 0–100% | 0 ≤ x < 100 |

#### Расширенные (Опциональные)
| Метрика | Описание | Формат | Валидация | Дефолт |
|---------|----------|--------|-----------|--------|
| **Time Horizon** | Горизонт планирования для графиков | 1–60 мес | 1 ≤ x ≤ 60 | 24 месяца |
| **Fixed Costs** | Постоянные расходы в месяц | ₽ | ≥ 0 | 0 ₽ |
| **Expansion Revenue** | Доп. выручка от существующих клиентов | 0–100% | 0 ≤ x ≤ 100 | 0% |
| **Discount Rate** | Ставка дисконтирования для NPV | 0–100% | 0 ≤ x ≤ 100 | 0% |
| **AOV** | Средний чек (для e-commerce) | ₽ | > 0 | 0 ₽ |
| **Purchase Frequency** | Частота покупок в год | число | > 0 | 0 |
| **Take Rate** | Комиссия платформы (для marketplace) | 0–100% | 0 < x ≤ 100 | 0% |

### 3.2 Производные метрики

#### 💎 LTV (Lifetime Value)
**SaaS:** `LTV = ARPU × Margin / Churn Rate`
**E-commerce:** `LTV = AOV × Purchase Frequency × Margin × Customer Lifespan`
⚠️ *Edge cases:* Churn Rate = 0 → LTV = ∞ (показать warning).

#### ️ LTV/CAC Ratio
`LTV/CAC = LTV / CAC`
| Значение | Статус | Цвет |
|----------|--------|------|
| < 1 | Убыточно | 🔴 Critical |
| 1–3 | Работает, но неоптимально | 🟡 Warning |
| **3–5** | **Золотой стандарт** | 🟢 Good |
| 5–10 | Отлично | 🟢 Excellent |
| > 10 | Возможно недоинвестируете | 🔵 Info |

#### ⏱ Payback Period
`Payback (мес) = CAC / (ARPU × Margin)`
| Значение | Статус |
|----------|--------|
| < 6 мес | Excellent |
| 6–12 мес | Good |
| 12–18 мес | Warning |
| > 18 мес | Critical |

####  Break-even Point
`Break-even (клиенты) = Fixed Costs / (ARPU × Margin − CAC × Churn Rate)`
⚠️ *Если знаменатель ≤ 0 → Break-even невозможен (показать ошибку).*

#### 📈 Net Revenue Retention (для SaaS)
`NRR = (Начальная выручка + Expansion − Churn) / Начальная выручка`

### 3.3 Формулы для графиков
- **Retention Curve:** `Retention(month) = (1 − Churn Rate)^month`
- **LTV Accumulation:** сумма `ARPU × Margin` по месяцам.
- **Sensitivity:** для параметра X от −50% до +50% построить `LTV(X)`.

## 🏗 4. Архитектура данных

### 4.1 Структура модели (Rust)
```rust
pub struct UnitModel {
    pub id: String,                    // UUID
    pub name: String,                  // Название модели
    pub business_type: BusinessType,   // SaaS / Ecommerce / Marketplace / Custom
    pub created_at: i64,               // Unix timestamp
    pub updated_at: i64,
    pub inputs: ModelInputs,
    pub metadata: Metadata,
}

pub struct ModelInputs {
    // Базовые
    pub cac: f64,
    pub arpu: f64,
    pub margin: f64,          // 0.0 - 1.0
    pub churn_rate: f64,      // 0.0 - 1.0
    
    // Расширенные (опциональные)
    pub time_horizon: Option<u32>,       // дефолт 24
    pub fixed_costs: Option<f64>,
    pub expansion_revenue: Option<f64>,
    pub discount_rate: Option<f64>,
    pub aov: Option<f64>,
    pub purchase_frequency: Option<f64>,
    pub take_rate: Option<f64>,
}
```

### 4.2 Формат файла `.uvault`
```text
[0–3]    Magic Bytes: "UVAU" (4 байта)
[4]      Version: 1 (1 байт)
[5–20]   Salt: 16 байт (для Argon2)
[21–32]  IV: 12 байт (для AES-GCM)
[33–N]   Encrypted Data
[N+1–N+32] HMAC-SHA256 (32 байта)
```

### 4.3 Алгоритм шифрования
1. **Serialize:** `UnitModel` → бинарный формат (`bincode`).
2. **Obfuscate:** кастомная обфускация (XOR + bit rotation) *[Учебная реализация]*.
3. **Derive Key:** `Argon2id(password, salt)` → 256-bit ключ.
4. **Encrypt:** `AES-256-GCM(key, IV, data)`.
5. **HMAC:** `HMAC-SHA256` для проверки целостности.

### 4.4 Версионирование формата
При открытии файла проверяется байт версии (индекс 4):
| Ситуация | Обработка |
|----------|-----------|
| `file_version > app_version` | Ошибка: *«Файл создан в более новой версии. Пожалуйста, обновите приложение»*. |
| `file_version < app_version` | Автоматическая миграция данных (добавление дефолтных значений для новых полей). |
| `file_version == app_version` | Нормальное чтение. |
| Magic bytes не совпадают | Ошибка: *«Файл повреждён или имеет неверный формат»*. |

##  5. Пользовательские сценарии

1. **Первый запуск:** Открывает приложение → "Создать новую модель" → Вводит параметры → Видит расчёт → Задаёт пароль → Сохраняет `.uvault`.
2. **Открытие модели:** Выбирает файл → Вводит пароль → Видит модель (или ошибку, если пароль неверен).
3. **Изменение параметров:** Двигает слайдер CAC → Все метрики и графики мгновенно пересчитываются → Сохраняет файл.
4. **Sensitivity Analysis:** Выбирает параметр → Видит график изменения LTV от −50% до +50% → Находит "красные линии" юнит-экономики.

## ⚠️ 6. Edge-cases и валидация

### 6.1 Математические
| Ситуация | Обработка |
|----------|-----------|
| Churn Rate = 0 | LTV = ∞, показать warning. |
| CAC = 0 | LTV/CAC = ∞, показать error. |
| Отрицательные значения | Запрет ввода, показать error. |
| Деление на ноль | Проверка перед расчётом, показать "N/A". |
| Числа > 10⁹ | Ограничение, показать warning. |

### 6.2 Пользовательские и системные

|----------|-----------|

| Файл от более новой версии | *«Файл создан в более новой версии. Обновите приложение»*. |

## ⚖️ 11. Trade-offs и принятые решения

1. **Tauri vs Electron:** Выбран Tauri ради размера бандла (~10MB vs ~150MB) и Rust backend.
2. **Solid.js vs React:** Выбран Solid.js ради производительности сигналов при частых пересчётах финансовых моделей и отсутствия Virtual DOM.
3. **Кастомная обфускация:** Реализована исключительно в учебных целях для демонстрации работы с битами в Rust. В README честно указано, что для продакшена достаточно AES.
4. **Бинарный формат (bincode) vs JSON:** Выбран бинарный формат ради меньшего размера файла, скорости и усложнения чтения без знания структуры.
5. **Local-first vs Cloud:** Выбрано локальное хранение ради полной конфиденциальности финансовых данных и отсутствия зависимости от интернета.
